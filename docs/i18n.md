# Internationalization

English is the default locale and uses clean URLs (`/`, `/services`, `/contact`). Spanish is published at `/es`, `/es/services`, and `/es/contact`. The middleware rewrites default-locale URLs to the internal `/en` route and redirects unsupported locale-like prefixes to English. Internal `/en/*` route URLs are canonicalized by page metadata to their clean English counterparts.

Messages live in `messages/en.json` and `messages/es.json`, organized by page/domain (`meta`, `nav`, `hero`, `services`, `contact`, and so on). Server components load the appropriate message object before rendering, so translated content and metadata are in the initial response. The quote form receives translated labels, validation-friendly native fields, and success/failure text as props.

## Add a locale

1. Add its code to `app/lib/site.ts`.
2. Create `messages/<locale>.json` matching the English message shape.
3. Add a static route entry through the existing `generateStaticParams` functions.
4. Add that locale's canonical paths and `hreflang` entries only after every public page has a real translation.
5. Extend the locale test to compare the new message file against English.

Missing keys are detected by the locale test's structural checks and TypeScript's shared message type. A locale is never advertised in metadata or the sitemap until it is in the supported locale list. Dates, numbers, and currencies should be formatted with `Intl.DateTimeFormat` and `Intl.NumberFormat` using the request locale when dynamic content requires them; no translated sentence is assembled from fragments.
